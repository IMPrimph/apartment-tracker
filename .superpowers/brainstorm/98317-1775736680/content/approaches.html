Redesign Approach

Three different ways to restructure the app around your workflow: glance → add → (occasionally) browse history

A

Single-Page Dashboard + Inline Add

Everything on one screen. A bold progress section at top with the 3 key numbers. Below it, a persistent inline quick-add form (type chips + amount + save). History tucked behind a "View transactions" expandable at the bottom.


Pros: Zero navigation. Open app → see progress → add cost → done. Fastest possible workflow.

Cons: Can feel dense on mobile if not carefully designed. History access requires scrolling past the form.

B

Dashboard + Bottom Sheet Add

Clean dashboard-only main view with the 3 key numbers as the entire screen. A prominent floating button opens a bottom sheet (slides up from bottom) for quick-add. History accessible via a small "History" link/tab.


Pros: Cleanest glance view — dashboard is completely uncluttered. Bottom sheet feels native on mobile. Clear separation of concerns.

Cons: One extra tap to start adding (tap FAB → sheet opens). Slightly more complex interaction model.

C

Tab-Based: Dashboard | Add | History

Three tabs at the bottom. "Dashboard" tab shows progress. "Add" tab is a dedicated quick-add screen. "History" tab shows all transactions. Each tab is focused on one task.


Pros: Very clear mental model — each task has its own space. Works well on mobile with bottom tab navigation.

Cons: Two taps to add (open app → tap Add tab → fill form). Dashboard and add are always separate, can't glance and add in one flow. Over-engineered for a personal tool with 3 features.

💡 My Recommendation: Option A

For a personal tool where your workflow is literally "open → glance → add → close", having everything on one screen with zero navigation is the fastest path. The inline form means you can see your progress update in real-time as you add costs. No modals, no tabs, no extra taps. Option B is a close second if you want a cleaner separation, but the extra tap adds friction to your most common action.
